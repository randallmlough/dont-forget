Implementation Notes: Route Local Item Writes Through Household Sync Coordinator

Design Decisions

  • Create the Household sync coordinator under lib/services/household/ as the app-owned policy module for sync status, subscriptions, lifecycle start/stop, in-flight guarding, retry cadence, expected sync interruption classification, and request reason to sync mode mapping.
  • Keep the Active List data source as the UI-facing adapter for local List/Item reads and low-level sync execution. The coordinator depends on its sync function instead of importing Active List types or UI code.
  • Let Active List keep local optimistic Item rendering and local write failure recovery, but consume coordinator status and request sync by reason after local add/check commits.
  • Coalesce in-flight sync requests inside the coordinator and preserve manual refresh as the highest-priority queued follow-up so explicit refresh still runs full sync behavior.

Tradeoffs Considered

  • The coordinator is created by the Active List provider for this slice so the visible behavior can move without broad Home composition churn. The public interface remains injectable and independent enough for Home to own construction in a later slice.
  • Kept the separate network status adapter out of this branch because this branch did not contain that module; coordinator offline state is driven by sync authorization and expected sync interruption errors for this slice.
