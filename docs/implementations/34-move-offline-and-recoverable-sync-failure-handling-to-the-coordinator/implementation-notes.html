Implementation Notes: Move Offline and Recoverable Sync Failure Handling to the Coordinator

Design Decisions

  • Keep the Household sync coordinator as the only boundary that classifies thrown sync failures into offline, failed, or quiet recovery behavior for Home-visible sync status.
  • Remove sync-operation error logging from the Active List data source and HouseholdStore so unexpected sync failures are logged once by the coordinator with the sync request reason.
  • Represent successful fallback recovery of a native sync failure as sync result metadata so the coordinator can keep recoverable checkpoint interruptions quiet and warn only for unexpected native failures that fallback recovered.
  • Keep HouseholdStore query and write error logging in place because those failures affect local data safety and should not be hidden as expected sync interruptions.

Tradeoffs Considered

  • Instead of moving the remote upsert fallback out of the data source in this slice, keep fallback execution there and move only classification/logging policy to the coordinator. This preserves the existing Active List data-source contract while addressing the noisy boundary.
