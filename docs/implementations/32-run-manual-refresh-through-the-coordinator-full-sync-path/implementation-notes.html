Implementation Notes: Run Manual Refresh Through the Coordinator Full-Sync Path

Design Decisions

  • Manual refresh now requests an explicit { mode: "full" } sync option from the Household sync coordinator instead of relying on an omitted option to imply full sync behavior.
  • The Active List refresh action remains the UI boundary that asks the coordinator for manual refresh, then reloads the visible List rows from the data source after the full sync request resolves.
  • Local Item writes continue to request { mode: "pushLocalOnly" } after manual refresh so automatic local-write sync does not start native full sync behavior.

Deviations From Spec

  • None yet.

Tradeoffs Considered

  • Kept manual refresh reload behavior in Active List instead of moving visible List loading into the coordinator. The coordinator owns sync mode and status policy; Active List still owns its rendered List state.
  • Kept the existing pull data-source method for now because it is still part of the data-source contract and tests, but manual refresh no longer calls it directly.
