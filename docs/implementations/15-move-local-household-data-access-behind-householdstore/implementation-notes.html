Implementation Notes: Move Local Household Data Access Behind HouseholdStore

Design Decisions

  • Issue #15 is implemented as a behavior-preserving hard cut from the legacy app-owned Household DB wrapper names to the domain-first HouseholdStore seam under lib/services/household/.
  • The native Turso sync package remains lazy-loaded inside the HouseholdStore wrapper so Jest, non-native code, and app-facing callers do not import the native module directly.
  • OpenHouseholdStoreConfig accepts an optional logger dependency so tests and non-app processes can capture or route HouseholdStore diagnostics without mocking the app logger module.
  • The reusable logger fixture lives in lib/test/mocks/logger.ts so future tests can inject a scoped logger without duplicating Jest mock shape.
  • The app-safe Household service index exports the Store seam and SQL/config types needed by current callers, while keeping test-only runtime and filename helpers out of the domain index.
  • The Turso clientName string remains dont-forget-household-db to avoid changing native sync identity or observability during a naming-only infrastructure migration.

Tradeoffs Considered

  • Kept this slice limited to the HouseholdStore wrapper and import migration rather than introducing ListService, ItemService, or ActiveListDataSource, because Issue #15 targets the shared infrastructure seam and explicitly asks to preserve existing Home and Active List behavior.
