Implementation Notes: Serialize and Coalesce Active Household Sync Requests

Design Decisions

  • The Household sync coordinator remains the single app-owned policy point for active Household sync request serialization, request coalescing, sync mode selection, and status transitions.
  • Queued requests keep only the highest-priority follow-up reason instead of storing every request. Manual refresh stays highest priority because it requires the full sync path; local writes stay ahead of passive foreground and retry requests.
  • Requests that arrive while sync is in flight resolve with the active sync chain, including any queued follow-up attempt that was needed by coalesced requests.

Tradeoffs Considered

  • The coordinator keeps a single queued reason rather than a request queue. The product requirement is to run another attempt when needed, not to preserve every trigger, and a single reason avoids duplicate native sync work.
