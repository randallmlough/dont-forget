Implementation Notes: Introduce Household Session Service for Home Startup

Design Decisions

  • Issue #16 is implemented as a behavior-preserving hard cut from app-facing bootstrap/cache module names to the Household Session service under lib/services/household/.
  • The Household Session service owns both fresh online session loading and cached non-secret Household Session metadata, while the existing server bootstrap response schema remains the HTTP trust-boundary parser for this slice.
  • createHouseholdSessionService provides injectable seams for external boundaries such as storage, fetch, and base URL; local Household data deletion stays on the production HouseholdStore path instead of being dependency-injected only for tests.
  • Cached Household Session reads now parse persisted JSON with Zod and strip unexpected Household DB auth token fields before returning metadata to callers.
  • HouseholdSessionService accepts an optional analytics dependency scoped to track and emits typed product events for successful online session loading, cache saving, and unauthorized cache invalidation.
  • Issue #47 later split sign-out cleanup into clearCachedHouseholdSessionMetadata and deleteCachedHouseholdSessionLocalData; the sign-out path still intentionally does not emit Household Session analytics because Home calls it after reset(), leaving user_signed_out as the tracking boundary.
  • The legacy lib/app/bootstrap-client.ts and lib/app/offline-bootstrap-cache.ts modules were deleted instead of kept as compatibility wrappers because all current app callers were migrated in this slice.
  • The persisted AsyncStorage key value remains the existing offline bootstrap key to avoid orphaning already-cached non-secret Household Session metadata during a naming migration.
  • Household Session cleanup tests assert the service calls the HouseholdStore local-data cleanup boundary; HouseholdStore's own tests cover the native filesystem deletion details.

Tradeoffs Considered

  • Renaming the persisted cache key would align the storage implementation detail with the new terminology, but it would discard existing offline startup metadata without improving runtime behavior.
