Implementation Notes: Own Retry Cadence and Foreground Sync Lifecycle in the Coordinator

Design Decisions

  • Keep retry cadence inside the Household sync coordinator and keep Active List responsible only for starting and stopping the coordinator while Home is mounted.
  • Use push-local-only sync for retry and local-write requests so automatic work avoids native pull loops while still attempting to propagate locally committed Household rows.
  • Treat app foreground transitions as a lifecycle request to the coordinator, with existing request serialization and coalescing deciding whether another sync attempt should actually run.
  • Drain a queued follow-up sync before rethrowing an unexpected manual refresh failure so local-write propagation is not stranded behind failed explicit refresh work.
  • Keep future network-awareness behind app-owned coordinator adapter boundaries instead of importing a network package into UI or data-source code.

Tradeoffs Considered

  • Keep a timer-based foreground retry cadence for this slice rather than adding a network dependency now. The PRD calls for a future network seam, but the acceptance criteria only require controlled retries and foreground lifecycle behavior.
