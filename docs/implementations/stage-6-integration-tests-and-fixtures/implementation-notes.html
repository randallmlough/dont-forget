Implementation Notes: Stage 6 Integration Tests And Fixtures

Design Decisions

  • Kept this slice valid against current origin/main. It adds fixture and harness foundations without importing Invitation, Household switching, or Household Join Code services from unmerged Stage 3, Stage 4, or Stage 5 branches.
  • Extended db/fixtures/ with real migrated directory DB scenarios for multi-Household active User selection, Invitation lifecycle variants, and Household Join Code use/attempt audit rows.
  • Added lib/test/api with only request construction and JSON response reading. More API helpers should be added after repeated handler-test duplication appears.
  • Extended analytics test support with a reusable assertion that tracked event payloads omit secret strings such as emails, visible Household Join Codes, and Invitation tokens.

Deferred PRD Coverage

Invitation service/API behavior, Household Join Code lifecycle services, failed-code throttling behavior, explicit Household switching behavior, route wrappers for future routes, and product analytics event emission remain dependent on unmerged service/API implementation stages. This slice intentionally documents that dependency instead of adding skipped tests against modules that do not exist on current main.

Tradeoffs Considered

  • Skipped tests were considered for the full PRD behavior matrix, but the repository does not currently use skipped/todo tests as a planning mechanism. Durable implementation notes plus passing fixture/harness tests keep the main branch green.
  • A richer API handler harness with dependency injection was deferred because current main only has the bootstrap API route. The first Invitation or Household Join Code handler tests should extend lib/test/api based on concrete duplication.
