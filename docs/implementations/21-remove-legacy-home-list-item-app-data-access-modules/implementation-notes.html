Implementation Notes: Remove legacy Home/List/Item app data-access modules

Design Decisions

  • Issue #21 is treated as the cleanup pass for the service-backed Home/List/Item path. The remaining touched legacy server bootstrap module belongs to Household Session startup, so it moves under lib/services/household/server/ instead of staying in top-level lib/server/.
  • The Turso platform helper moved with the Household bootstrap service because it is only used by Household server provisioning and should not remain as a separate top-level server data-access helper for this path.
  • lib/server/auth remains in place because it is an authentication boundary, not a Home/List/Item data-access module touched by this cleanup slice.
  • The Household Session cache key now uses Household Session language instead of the old offline bootstrap name, matching the hard-cut cleanup posture for stale naming.

Deviations From Spec

  • None yet.

Tradeoffs Considered

  • Keeping a compatibility wrapper at lib/server/bootstrap would reduce import churn, but the issue explicitly asks to remove legacy touched modules instead of preserving wrappers.
  • Preserving the previous cached Household Session storage key would avoid invalidating local developer cache data, but that would keep stale bootstrap terminology in the active app path.
